# status-and-check Specification

## Purpose
Состояние проекта для людей и CI: `status` сообщает текущую и последнюю версию и мажорный подъём, `check` падает на неразрешённых конфликтах (ТЗ: §Commands).

## Requirements

### Requirement: Команда status

`rootstock status [--format json]` SHALL выводить текущую версию проекта, последнюю доступную версию и признак мажорного подъёма (ТЗ: §Commands, `status`). Мажорный подъём — мажор цели больше мажора текущей версии. «Последняя» — последний semver-тег. Вывод идёт в stdout, JSON — по `--format json`.

#### Scenario: Есть новая минорная версия
- **WHEN** проект на `v1.0.0`, последний тег `v1.2.0`
- **THEN** статус показывает текущую `v1.0.0`, последнюю `v1.2.0`, мажорный подъём — нет

#### Scenario: Есть новая мажорная версия
- **WHEN** проект на `v1.4.0`, последний тег `v2.0.0`
- **THEN** мажорный подъём — да

#### Scenario: Формат JSON
- **WHEN** задан `--format json`
- **THEN** stdout содержит один JSON-документ с теми же полями

### Requirement: Команда check

`rootstock check` SHALL завершаться ненулевым кодом, если любой managed-файл содержит неразрешённые маркеры конфликта или запись не согласована с деревом (ТЗ: §Commands, `check`). Команда предназначена для CI.

#### Scenario: Маркеры в управляемом файле
- **WHEN** managed-файл содержит строку `<<<<<<< project`
- **THEN** `check` завершается ненулевым кодом и называет файл

#### Scenario: Всё согласовано
- **WHEN** маркеров нет и запись согласована с деревом
- **THEN** код 0
