# template-format Specification

## Purpose
Формат шаблона rootstock: `rootstock.toml`, вопросы, рендер файлов и имён, окружение Jinja, классы файлов и хуки (ТЗ: §Template format, §Concepts).

## Requirements

### Requirement: Конфигурация шаблона в rootstock.toml

Шаблон SHALL описывать себя файлом `rootstock.toml` в корне шаблона (ТЗ: §Template format; §Left to the builder: файл несёт номер версии схемы). Файл MAY задавать минимальную версию rootstock.

#### Scenario: Корень шаблона в подкаталоге
- **WHEN** `rootstock.toml` указывает подкаталог корня шаблона
- **THEN** в проект попадают только файлы из этого подкаталога

### Requirement: Вопросы шаблона

Шаблон SHALL объявлять упорядоченные вопросы типов `bool`, `str`, `int`, `choice`, `multichoice`, `yaml`, у каждого — необязательные `help`, `default`, `when`, `validator` (ТЗ: §Template format, пункт «Questions»). `default` MAY быть выражением Jinja над предыдущими ответами. Вопрос с ложным `when` MUST не задаваться, принимать значение по умолчанию и не записываться в запись проекта. `validator` MUST рендериться в сообщение об ошибке, пустое при допустимом значении.

#### Scenario: Вопрос с ложным when
- **WHEN** у вопроса `when` вычисляется в ложь
- **THEN** вопрос не задаётся, а его ответ отсутствует в `.rootstock.toml`

#### Scenario: Значение по умолчанию из прежних ответов
- **WHEN** `default` вопроса ссылается на ответ предыдущего вопроса
- **THEN** при `--defaults` вопрос получает вычисленное значение

#### Scenario: Валидатор отклоняет ответ
- **WHEN** `validator` рендерится в непустую строку для заданного через `--data` ответа
- **THEN** ответ отклоняется и выводится сообщение валидатора

### Requirement: Рендер файлов и имён

Файлы с суффиксом `.jinja` (суффикс настраивается) SHALL рендериться с отбрасыванием суффикса; остальные файлы MUST копироваться байт в байт. Имена файлов и каталогов MUST рендериться всегда; имя, отрендеренное в пустую строку, не создаётся (ТЗ: §Template format, пункт «Templated files»). Корень шаблона MAY быть подкаталогом, заданным в конфигурации.

#### Scenario: Условное имя файла
- **WHEN** файл называется `{% if rust %}Cargo.toml{% endif %}.jinja`, а ответ `rust` ложен
- **THEN** файл в проекте не создаётся

#### Scenario: Нешаблонный файл копируется как есть
- **WHEN** в шаблоне лежит файл без суффикса `.jinja` с текстом `{{ x }}`
- **THEN** в проекте он содержит ровно `{{ x }}`

### Requirement: Настройки окружения Jinja и подключения

Шаблон SHALL настраивать `trim_blocks`, `lstrip_blocks`, `keep_trailing_newline`; `keep_trailing_newline` по умолчанию истинен (ТЗ: §Template format, «Jinja environment options»). `{% include %}` и `{% import %}` MUST разрешаться относительно каталога шаблона — каталога с `rootstock.toml`, а не корня шаблона; база подключений не настраивается (ТЗ: §Template format, «Includes», 1.1). Настроенные каталоги частичных шаблонов MUST не попадать в результат. Фильтры и тесты — встроенные minijinja плюс `regex_search` (ТЗ: §Template format).

На значениях SHALL вызываться Python-методы с семантикой Python (ТЗ: §Template format, 1.2):
- строк — `startswith`, `endswith`, `lower`, `upper`, `strip`, `lstrip`, `rstrip`, `split`, `replace` и другие из набора design D1;
- словарей — `items`, `keys`, `values`, `get`;
- списков — `count` и `append`.

`append` у списка, заведённого `{% set x = [] %}`, MUST менять этот список на месте: добавленное видно после цикла и после выхода из блока, где вызван метод (ТЗ: §Template format, 1.2). `append` у другого списка и метод вне набора MUST быть ошибкой рендера (design D3). Метод MUST вызываться одинаково в содержимом файлов, в именах, в подключаемых файлах, в `default`, `validator` и в правилах классов файлов (design D4).

#### Scenario: Завершающий перевод строки сохраняется
- **WHEN** шаблонизируемый файл заканчивается переводом строки, а настройки не менялись
- **THEN** отрендеренный файл заканчивается тем же переводом строки

#### Scenario: Частичный шаблон не выводится
- **WHEN** каталог `partials` указан как каталог частичных шаблонов и из файла сделан `{% include "partials/a.jinja" %}`
- **THEN** содержимое включается в результат, а самого каталога `partials` в проекте нет

#### Scenario: Подключение от каталога шаблона
- **WHEN** корень шаблона — `template/`, а файл в нём делает `{% include "template/_partials/x.jinja" %}`
- **THEN** подключается `template/_partials/x.jinja` из каталога с `rootstock.toml`

#### Scenario: Ключ include_root отклоняется
- **WHEN** `rootstock.toml` содержит ключ `include_root`
- **THEN** конфигурация отклоняется как содержащая неизвестный ключ, код 1 (design D5)

#### Scenario: Строковый метод
- **WHEN** файл содержит `{{ path[:-3] if path.endswith('.md') else path }}`, а ответ `path` — `k/oq.md`
- **THEN** в проекте `k/oq`

#### Scenario: Список, собранный append во вложенных циклах
- **WHEN** макрос заводит `{% set names = [] %}`, во вложенном цикле вызывает `{% set _ = names.append(name) %}`, затем выводит `{{ names | join(", ") }}`
- **THEN** выводятся все добавленные имена в порядке добавления

#### Scenario: append у другого списка
- **WHEN** файл вызывает `append` у списка `{% set x = [1] %}`
- **THEN** рендер завершается ошибкой, код 1, ничего не записано

#### Scenario: Шаблон с set в raw-блоке
- **WHEN** в `{% raw %}…{% endraw %}` стоит текст `{% set x = [] %}`
- **THEN** этот текст выводится как есть

### Requirement: Классы файлов

Каждый путь SHALL относиться к одному из классов `managed` (по умолчанию), `starter`, `excluded` по спискам glob-шаблонов в стиле gitignore, вычисляемым над отрендеренным путём (ТЗ: §Concepts «File classes», §Template format «Class rules»). Шаблоны MAY содержать Jinja над ответами и MUST рендериться с ответами на каждой стороне, включая базовый рендер при обновлении.

#### Scenario: Шаблон класса с ответом
- **WHEN** правило `starter` равно `{{ spec_path }}/**`, а `spec_path` равен `docs/design.md`
- **THEN** файлы под этим путём получают класс `starter`, а не совпадают с `/**`

#### Scenario: Исключённый файл
- **WHEN** путь совпал с правилом `exclude`
- **THEN** файл не попадает в проект и не входит в инвентарь

### Requirement: Хуки шаблона

Шаблон SHALL объявлять хуки — команды оболочки с `when` равным `new`, `update` или обоими; они запускаются в каталоге проекта после записи файлов (ТЗ: §Template format «Hooks»). Хуки MUST запускаться только с `--trust` или после интерактивного подтверждения. Хук SHALL запускаться как `sh -c <команда>`. На Windows `sh` — оболочка Git for Windows, найденная рядом с `git`; если её нет, а хуки фазы будут запущены, команда MUST завершиться ошибкой до первой записи (1.4).

#### Scenario: Хук без доверия
- **WHEN** шаблон объявляет хук, а `--trust` не задан и подтверждения нет
- **THEN** хук не запускается

#### Scenario: Хук с --trust
- **WHEN** хук с `when = "new"` объявлен и задан `--trust`
- **THEN** после записи файлов команда хука исполняется в каталоге проекта

#### Scenario: POSIX-хук на Windows
- **WHEN** на Windows хук `if command -v true >/dev/null; then echo ok > out; fi` запускается с `--trust`
- **THEN** в проекте появляется файл `out`

### Requirement: Запись проекта в каталоге шаблона

Если корень файлов шаблона совпадает с каталогом шаблона, `.rootstock.toml` на верхнем уровне этого каталога SHALL пропускаться при рендере, как `rootstock.toml`. Это запись самого репозитория шаблона как проекта rootstock, а не файл шаблона (ТЗ: §Template format, «Template root», 1.3). Шаблонный файл, который рендерится в имя записи где-либо ещё, MUST по-прежнему быть ошибкой рендера.

#### Scenario: Шаблон с собственной записью
- **WHEN** корень файлов — сам каталог шаблона, и в нём рядом с `rootstock.toml` лежит `.rootstock.toml`
- **THEN** `new` создаёт проект без чужой записи; в проекте только его собственный `.rootstock.toml`

#### Scenario: Шаблонный файл в имя записи
- **WHEN** файл `{{ x }}.jinja` рендерится в `.rootstock.toml`
- **THEN** рендер завершается ошибкой, ничего не записано
