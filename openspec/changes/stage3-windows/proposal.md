## Why

ТЗ обещает сборки под Linux, macOS и Windows (§Constraints), а ревизия 1.4 решила, как на Windows ведут себя хуки, бит исполнения и символические ссылки. Сейчас код держится на допущениях Unix:
- хук запускается через `sh`, которого на Windows по умолчанию нет в `PATH`;
- бит исполнения читается с диска, а на Windows его нет; проект harness, созданный на Windows, теряет `+x` у всех `.harness/hooks/*.sh`;
- запись ссылки на Windows — ошибка «not supported»;
- выгрузка шаблона идёт с пользовательским `core.autocrlf`, и Git for Windows по умолчанию превращает LF в CRLF, нарушая правило 8.

Это второй change этапа 3. Релиз v0.1.0 (решение владельца 30.10.2026) ставится только после него и зелёного CI на трёх ОС.

## What Changes

- **Режимы из дерева git.** Бит исполнения и ссылки шаблона берутся из дерева git выгруженного commit'а (`100755`, `120000`), а не с диска. Для рендера `HEAD` — из индекса, неотслеживаемые файлы — с диска (ТЗ: §How update works, п. 7, 1.4).
- **Байты выгрузки.** Шаблон выгружается с `core.autocrlf=false`, на любой ОС и при любом пользовательском конфиге git (ТЗ: п. 8).
- **Бит исполнения проекта на Windows.** Где у файловой системы нет бита исполнения, rootstock ставит его в индекс git проекта и оттуда же читает бит проекта (п. 7, 1.4).
- **Ссылки на Windows.** Создаются настоящие ссылки. Если система отказывает, это ошибка до записи с подсказкой, как разрешить (п. 7, 1.4).
- **Хуки на Windows.** `sh -c` из Git for Windows, найденный рядом с `git`. Без него команда с хуками к запуску останавливается до записи (§Template format, «Hooks», 1.4).
- **CI на трёх ОС.** Тесты гоняются на Windows и macOS, кроме Linux.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `project-update`: «Права и симлинки» — источник режимов, бит в индексе, отказ системы в ссылке; «Байты на входе — байты на выходе» — выгрузка без `autocrlf`.
- `template-format`: «Хуки шаблона» — оболочка хуков на Windows.

## Не входит

- Workflow релиза, метаданные crates.io, тег v0.1.0 — следующий шаг, отдельным PR после этого change.
- Homebrew (ТЗ: «later»).
- Бит исполнения в индексе на Unix: там он остаётся на диске, как раньше.

## Impact

- **Код:**
  - `src/source.rs` — режимы путей в `Checkout`, `core.autocrlf=false` при выгрузке;
  - `src/render.rs` — режимы из выгрузки поверх диска;
  - `src/apply.rs` — бит проекта из индекса, бит в индекс, ссылки на Windows, проба ссылки до записи;
  - `src/hooks.rs` — поиск `sh`;
  - `src/commands/{new,update}.rs` — вызовы новых проверок до записи и индекса после записи.
- **Тесты:** сквозные тесты собираются и проходят на Windows; новые тесты на режимы из дерева и `autocrlf`.
- **CI:** `.github/workflows/ci.yml` — джоба тестов на `windows-latest` и `macos-latest`.
- Формат записи и конфигурации не меняется.
