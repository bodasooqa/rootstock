## MODIFIED Requirements

### Requirement: Маркеры конфликта

Маркеры SHALL быть в стиле git: `<<<<<<< project`, `=======`, `>>>>>>> template vX.Y.Z` — каждый в начале строки (ТЗ: §How update works, п. 9). Результат трёхстороннего слияния текста SHALL совпадать с выводом `git merge-file` в стиле `merge` на тех же трёх входах с теми же подписями маркеров. Совпадают и чистый результат, и решение «чисто или конфликт», и границы конфликтных областей (ТЗ: §Left to the builder; §Stages, п. 2 — обновление даёт то же дерево, что `copier update`). Конфиг git пользователя и репозитория проекта MUST не влиять на результат слияния. Отказ git при слиянии MUST давать код 1 до первой записи в проект (ТЗ: §How update works, п. 11).

#### Scenario: Пересекающиеся правки
- **WHEN** проект и шаблон изменили одну и ту же строку
- **THEN** файл содержит блок с тремя маркерами, где версия в последнем — целевой тег

#### Scenario: Одинаковая правка на краю конфликта
- **WHEN** обе стороны одинаково изменили строку, а следом добавили разные строки
- **THEN** одинаково изменённая строка стоит перед `<<<<<<< project`, внутри маркеров только различающиеся строки

#### Scenario: Слияние, чистое для git
- **WHEN** правки сторон не пересекаются по меркам `git merge-file`
- **THEN** файл слит без маркеров, конфликта нет

#### Scenario: Конфиг git с diff3
- **WHEN** в глобальном конфиге git задано `merge.conflictStyle = diff3`, и обновление даёт конфликт
- **THEN** в файле нет строки `|||||||`, блок состоит из трёх маркеров стиля `merge`
