## Context

Мотивация — `proposal.md`. Что известно о входе и о текущем коде:

- **`copier.yml` harness** (v0.4.5; у v0.3.3 те же ключи и типы):
  - `_min_copier_version`, `_subdirectory: template`, `_answers_file`, `_templates_suffix: .jinja`;
  - `_envops`: три флага, все true;
  - `_exclude`: `_partials` и 24 записи «только при обновлении», две их формы — `{% if _copier_operation == 'update' %}P{% endif %}` и `{% if _copier_operation == 'update' and C %}P{% endif %}`;
  - `_tasks`: одна задача с `when: "{{ _copier_operation == 'copy' }}"`;
  - `_skip_if_exists`: шаблоны с ведущим `/` и с Jinja вида `{% if C %}P{% endif %}`;
  - вопросы `str`, `bool`, `yaml`, один `str` с `choices`-словарём, `when` вида `"{{ E }}"`.

  В `template/` переменные Copier встречаются только в `{{ _copier_conf.answers_file }}.jinja`. Его содержимое — строка-комментарий и `{{ _copier_answers|to_nice_yaml -}}`. Симлинков под `template/` нет.
- **Copier 9.19** (исходники установленного пакета):
  - `_exclude` и `_skip_if_exists` сверяются с отрендеренным путём назначения, как у rootstock;
  - `_exclude` целиком заменяет список по умолчанию `DEFAULT_EXCLUDE`, а при непустом `_subdirectory` умолчание пусто;
  - `_envops` по умолчанию — только `keep_trailing_newline: true`;
  - команда задачи-строки рендерится Jinja и идёт через оболочку;
  - `_preserve_symlinks` по умолчанию false, то есть ссылки разыменовываются.
- **rootstock:**
  - `TemplateConfig` выводит только `Deserialize`, сериализации нет;
  - `exclude` проверяется до рендера содержимого: исключённые частичные файлы не рендерятся сами;
  - имя `{{ _copier_conf.answers_file }}.jinja` при рендере падает: атрибут у неопределённого значения (проверено на этапе планирования);
  - `hooks.rs` запускает `run` через `sh -c` без Jinja.

Затронутые модули и граф:
- **Ядро** — новый `src/copier.rs`. Он читает `copier.yml` и дерево шаблона, то есть checkout, и ничего не пишет. Git, терминала и stderr у него нет. От других модулей ядра он берёт только `config::parse` для проверки вывода.
- **Края:**
  - новая команда `src/commands/import_copier.rs` пишет `rootstock.toml` и удаляет файл ответов;
  - `src/cli.rs` получает подкоманду.

Граф зависимостей не нарушается.

Контракты из таблицы «Источники правды» не меняются: формат `rootstock.toml` прежний, конвертер лишь его выдаёт.

## Goals / Non-Goals

**Goals:**
- одна функция преобразования, которую позже вызовет и сторона проекта, без записи на диск;
- полный список неподдерживаемого за один проход;
- `copier.yml` harness обоих тегов конвертируется без находок.

**Non-Goals:**
- сторона проекта;
- паритет рендера (это `stage2-parity`);
- `--force` и перезапись существующего `rootstock.toml`.

## Decisions

**D1. Где и когда команда работает.** `import-copier` без аргументов работает в текущем каталоге.

| В каталоге | Результат |
|---|---|
| `copier.yml` или `copier.yaml` (Copier принимает оба) | сторона шаблона |
| оба файла | ошибка, как у Copier (`MultipleConfigFilesError`) |
| ни одного | ошибка «no copier.yml here»; сторону проекта добавит следующий change |
| уже есть `rootstock.toml` | ошибка до любой записи |

YAML должен быть одним документом.
- *Отвергнуто.* `--force`: перезапись конфига, который мог быть написан руками, без пользы для одноразовой конвертации.

**D2. Вывод собирается как TOML-таблица и проверяется разбором.** `copier.rs` строит `toml::Table`, печатает его через `toml::to_string` и разбирает результат через `config::parse`. Наружу отдаётся пара: текст и `TemplateConfig`. Ошибка разбора — внутренняя ошибка конвертера с текстом причины, на диск ничего не попадает. Текст начинается с комментария `# Converted from copier.yml by rootstock import-copier.`
- *Почему.* Так записанный файл и конфиг в памяти (его возьмёт сторона проекта) — одно и то же. Сериализацию в `config.rs` добавлять не нужно, контракт `TemplateConfig` не трогается.
- *Отвергнуто.* `Serialize` у `TemplateConfig`: появились бы два описания формата, которые разъедутся.

**D3. Строки переносятся дословно.** Ни один шаблон Jinja не переписывается, кроме двух случаев: `when` вопроса (D8) и разобранных форм `_copier_operation` (D6, D7). Это шаблоны в правилах, `default`, `validator`, `help`, `_subdirectory`, `_templates_suffix`.
- *Почему.* Семантика Jinja у Copier и rootstock задана ТЗ одинаковой; переписывание — место для тихих расхождений.

**D4. Умолчания Copier выписываются явно.**
- `trim_blocks`, `lstrip_blocks` и `keep_trailing_newline` пишутся всегда, даже если совпадают с умолчанием rootstock.
- Нет `_exclude`, а корень шаблона — сам каталог шаблона → `exclude` = `DEFAULT_EXCLUDE` Copier 9.19 дословно: `copier.yaml`, `copier.yml`, `~*`, `*.py[co]`, `__pycache__`, `.git`, `.DS_Store`, `.svn`. Корень — сам каталог, когда `_subdirectory` нет или он после нормализации пуст: `""`, `.`, `./`. Это повторяет проверку Copier `Path(subdirectory) == Path()`.
- Есть `_exclude` или корень — подкаталог → умолчание не добавляется, как у Copier. Тогда `copier.yml` в корне шаблона выпускается, ровно как его выпустил бы Copier.
- Корень пишется нормализованным: без `.`-компонентов и завершающего `/`, пустой — как `.`.
- *Почему.* Цель этапа — байтовый паритет с Copier; неявное умолчание rootstock могло бы с ним разойтись.

**D5. `_min_copier_version` и `_answers_file` отбрасываются.** `min_rootstock` не выставляется. ТЗ включает оба ключа в подмножество, но не даёт им соответствия.
- Минимальная версия Copier ничего не говорит о версии rootstock.
- Имя файла ответов прочитает сторона проекта из самого `copier.yml` того тега.

**D6. Исключения «только при обновлении» отбрасываются, только если есть пара.** Распознаются две формы, без учёта пробелов внутри `{% %}`, кавычки `'` или `"`:
- `{% if _copier_operation == 'update' %}P{% endif %}`;
- `{% if _copier_operation == 'update' and C %}P{% endif %}`.

Парой считается запись `_skip_if_exists`, совпадающая после обрезки пробелов по краям: для первой формы `P`, для второй `{% if C %}P{% endif %}`. Без пары исключение — находка «update-only exclude without a matching `_skip_if_exists` entry».

Форма не распознаётся, а запись идёт в проверку D11 (и даёт находку на `_copier_operation`), если:
- в `P` есть `{%` или `%}`: иначе `{% else %}` или вторая пара `{% endif %}…{% if %}` молча ушли бы в `starter`;
- в `C` есть слово `or`, `if` или `else`: у них приоритет ниже `and`, и перенос `C` в `{% if C %}` изменил бы смысл.
- *Почему.* ТЗ отбрасывает их «as redundant once those paths are starter». Избыточность и проверяется, иначе конвертация тихо сменила бы поведение на обновлении.
- *Отвергнуто.* Отбрасывать любые записи с `_copier_operation == 'update'`, не глядя: не ловит шаблон, где путь не стартовый.

**D7. Задачи.** Распознаётся задача-строка или словарь из `command` (строка) и необязательного `when`.

| `when` | Фаза хука |
|---|---|
| нет или YAML `true` | обе |
| `{{ _copier_operation == 'copy' }}` | `new` |
| `{{ _copier_operation == 'update' }}` | `update` |

Пробелы внутри `{{ }}` любые, кавычки `'` или `"`.

Находка, если у задачи:
- иное `when`;
- команда-список;
- ключ `working_directory` или любой другой;
- `{{`, `{%` или `{#` в команде. Copier рендерит команду, а хуки rootstock — нет; без отказа Jinja ушла бы в оболочку буквально.
- *Отвергнуто.* Рендерить `run` хуков rootstock: это новое поведение формата, которого нет в ТЗ.

**D8. Вопросы.**
- `type` обязателен. Вывод типа из дефолта, как у Copier, не делается: harness всегда пишет тип, а угадывание — источник тихих расхождений.
- `str` с `choices` → `choice`:
  - словарь: ключ — подпись, значение — значение;
  - список скаляров: значение и подпись сразу.
- `when`:
  - строка вида `{{ E }}` (с `{{-`/`-}}`) → `E`, если внутри нет `{{`, `}}` и `{%`;
  - YAML-булево — `"true"` или `"false"`, то есть выражение, которое понимает rootstock;
  - иное — находка.
- `default` переводится из YAML в TOML структурой. `null` где угодно — находка: у TOML нет пустого значения.
- `help`, `validator` и строковый `default` — дословно.
- Поля кроме шести перечисленных — находка (`secret`, `placeholder`, `multiselect`, `multiline`, `qmark` и прочие).
- Простая форма вопроса Copier, `name: value` без словаря, — находка: в ней нет типа.

**D9. Файл ответов узнаётся по имени.** Удаляется файл прямо в корне шаблона (`<template dir>/<root>/`), имя которого — `{{ _copier_conf.answers_file }}` с любыми пробелами внутри `{{ }}` плюс суффикс. Содержимое не проверяется: у harness в нём ещё и строка-комментарий, а сам файл уходит целиком. Такой же файл глубже корня — находка по D11.

**D10. Находки копятся, а не обрывают проход.** `copier.rs` возвращает либо результат, либо `Unsupported(Vec<Finding>)`. Находка — строка вида `` `<где>`: <что> ``, например `` `_jinja_extensions`: key not supported `` или `` question `x`: type `int` not supported ``. Команда печатает в stderr заголовок `copier.yml uses features rootstock cannot convert:` и по строке на находку, код 1. Разбор YAML и чтение файлов — обычные ошибки, они обрывают проход сразу.

**D11. Где ищутся переменные Copier.** Регулярное выражение `\b(_copier_\w*|_folder_name|_external_data)\b` проверяется:
- на всех строках вопросов, `_skip_if_exists`, оставшихся `_exclude` и команд задач — кроме разобранных форм D6 и D7;
- на всех именах под корнем шаблона;
- на содержимом всех файлов под корнем, которые читаются как UTF-8, включая нешаблонизируемые: подключить можно и их.

Файл ответов (D9) не проверяется. `.git` не обходится.
- *Цена.* Нешаблонизируемый текст, просто упоминающий `_copier_answers`, остановит импорт ложной находкой. В harness таких нет (проверено поиском по `template/` v0.4.5); ложный отказ лучше тихо пропущенной подстановки.

**D12. Симлинк под корнем шаблона — находка.** Copier по умолчанию его разыменовывает, а rootstock воспроизводит ссылкой (ТЗ: §How update works, п. 7). `_preserve_symlinks` не входит в подмножество и тоже находка, даже со значением true.

**D14. Корень шаблона проверяется до обхода.** `_subdirectory` проверяется по правилам `root` из `config` до того, как что-либо читается под ним:
- путь относительный;
- без `..`;
- без `\`, `:` и NUL.

Затем каждый префикс корня проверяется через `symlink_metadata`.

| Что с корнем | Итог |
|---|---|
| нарушено правило выше | находка `` `_subdirectory`: must be a relative path inside the template `` |
| ссылка на любом префиксе | находка «template root goes through a symbolic link» |
| корня нет | находка «template root does not exist» |
| корень не каталог | находка «template root is not a directory» |
| иная ошибка ввода-вывода | ошибка `Io`, проход обрывается |

При любой находке по корню обход не запускается, и удалять нечего.
- *Почему.* Ревью нашло: без этого `_subdirectory: ../x` или ссылка посередине пути уводили обход за шаблон. Файл ответов удалялся вне каталога шаблона.

**D15. Обход отклоняет то, на чём потом упадёт рендер.** Под корнем находкой становятся:
- имя не в UTF-8;
- FIFO, сокет или устройство.

Рендер (`render.rs`) отклоняет те же случаи, и импорт не должен проходить там, где первый `new` упадёт.

**D16. Поиск конфига Copier.** `copier.yml` или `copier.yaml` должен быть обычным файлом. Ссылка или каталог с таким именем — ошибка, как у `config::load` для `rootstock.toml`: шаблон недоверенный. Ошибка `symlink_metadata`, кроме NotFound, — ошибка ввода-вывода, а не «файла нет». В сообщениях называется тот файл, что прочитан.

**D17. Права `rootstock.toml`.** Файл получает `0644`, как обычный файл репозитория. Временный файл `tempfile` создаётся с `0600`, и без явной установки прав `rootstock.toml` унаследовал бы их.

**D13. Порядок записи.** Сначала проходит вся конвертация и проверка (D2), потом пишется `rootstock.toml`. Запись идёт во временный файл в том же каталоге и переименовывается без перезаписи. Последним удаляется файл ответов. Если удаление не удалось, код 1 и сообщение о том, что `rootstock.toml` уже записан (ТЗ: §How update works, п. 11 — «a clear statement of what was»). Итог печатается в stderr строками `wrote rootstock.toml` и `removed <path>`; stdout пуст.

## Risks / Trade-offs

- [PyYAML читает YAML 1.1, `serde_norway` — 1.2: неквотированные `yes`/`on` у Copier булевы, у нас строки] → в harness таких нет. Различие проявится в `stage2-parity`, если появится; записано здесь.
- [Подключение файла вне корня шаблона, который не сканируется по D11] → переменная Copier там отрендерится пустой. В harness подключения только из `template/_partials/`.
- [Отказ по D11 на безобидном упоминании] → сообщение называет файл. Владелец шаблона видит причину и может переписать текст.
- [`when` вопроса у Copier рендерится в строку и проходит `cast_to_bool`: строки `"no"`, `"0"`, `"off"`, `"none"` ложны. В rootstock выражение `E` вычисляется по истинности Jinja, и непустая строка истинна] → у harness все `when` булевы (`rust`, `linear`, `not (rust and frontend)`). Расхождение возможно у шаблона, где `when` — строковый ответ. Найдено spec-auditor'ом.
- [Шаблоны harness вызывают Python-методы `list.append` и `str.endswith`, которых нет в minijinja] → импорт проходит, но рендер падает. Владелец решил поддержать их в rootstock (30.10.2026): ревизия ТЗ 1.2 и отдельный change.
- [Сравнение пары в D6 строковое: эквивалентные, но по-разному записанные шаблоны дадут находку] → harness пишет пары одинаково; ложный отказ безопасен.
