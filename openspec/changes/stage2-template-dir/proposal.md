## Why

Этап 2 — «Copier import and parity». ТЗ ревизии 1.1 включает в этот этап две доработки формата и источников (§Stages, п. 2), и конвертер `import-copier` на них опирается.

Первая — каталог шаблона. Подключения резолвятся только от каталога с `rootstock.toml`, а не от настраиваемого ключа `include_root`. Конвертер не должен ни выдавать этот ключ, ни зависеть от него.

Вторая — подкаталог шаблона в репозитории. Он задаётся одинаково для любого источника, флагом `new --subdir`. Сейчас подкаталог возможен только у локального пути, хотя §Concepts допускает его у любого репозитория.

Change идёт первым на этапе: он маленький и меняет формат шаблона и записи, на которые потом ляжет конвертер.

## What Changes

- **`new --subdir <path>`.** Флаг задаёт каталог шаблона внутри источника для `https://…`, `git@…`, `gh:` и локального пути (ТЗ: §Commands, 1.1).
  - Путь записывается в `.rootstock.toml` рядом с источником; `update` и `status` берут его оттуда без флага.
  - Путь, выходящий за источник, абсолютный или содержащий запрещённые символы, отклоняется.
  - Подкаталог без `rootstock.toml` — ошибка.
- **Запись проекта** получает необязательное поле с подкаталогом (ТЗ: §Concepts «Record», 1.1). Записи без него читаются как прежде, `schema` остаётся `1`.
- **Подключения.** `{% include %}` и `{% import %}` резолвятся от каталога шаблона, то есть каталога с `rootstock.toml`; база не настраивается (ТЗ: §Template format «Includes», 1.1).
- **BREAKING.** Ключ `include_root` в `rootstock.toml` удалён. Конфиг с ним отклоняется как конфиг с неизвестным ключом. Опубликованных rootstock-шаблонов пока нет.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `project-creation`: источники шаблонов — флаг `--subdir` для любого источника; запись хранит подкаталог.
- `project-update`: `update` берёт шаблон из подкаталога, записанного в `.rootstock.toml`.
- `template-format`: подключения резолвятся от каталога шаблона; ключа `include_root` нет.

## Impact

- **Код:**
  - `src/source.rs`: подкаталог в checkout'е, в том числе для `HEAD` локального источника;
  - `src/record.rs`: поле записи;
  - `src/config.rs`, `src/render.rs`, `src/jinja.rs`, `src/commands/mod.rs`: удаление `include_root`;
  - `src/cli.rs`, `src/commands/{new,update,status}.rs`: флаг и передача подкаталога.
- **Контракты** из таблицы «Источники правды»: схемы `rootstock.toml` и `.rootstock.toml` — формат записанных данных; процедура `contract-change`. Старые записи без поля остаются читаемыми.
- **Документация:** `README.md` (быстрый старт, формат шаблона).
- **Тесты:** `tests/source.rs`, `tests/cli_new_update.rs`, unit-тесты `config` и `render`.

## Не входит

- `import-copier` в обоих режимах — следующий change этапа.
- Синтаксис подкаталога внутри URL (`repo//sub`): ТЗ 1.1 выбрало флаг.
- Смена подкаталога у существующего проекта (`update --subdir`): ТЗ называет флаг только у `new`.
- Перевод записи локального источника в форму «корень репозитория плюс подкаталог»: путь, указывающий прямо в подкаталог, остаётся допустимым (ТЗ: §Commands, 1.1).
