## Context

Мотивация — `proposal.md`, решение владельца — ревизия ТЗ 1.2.

Текущее состояние кода:
- `src/jinja.rs` строит одно `Environment` из опций шаблона;
- `render_str` рендерит любой текст: содержимое, имена, правила, `default`, `validator`;
- загрузчик `load_include` читает подключаемые файлы под каталогом шаблона;
- `eval_bool` вычисляет `when` как выражение;
- колбэка неизвестных методов нет.

Факты о minijinja 3.0.4:
- значения неизменяемы: литерал `[]` даёт `Arc<Vec<Value>>` без внутренней изменяемости;
- колбэк неизвестного метода получает `&Value` и изменить список не может.

`minijinja-contrib` 3.0.4 с возможностью `pycompat` даёт `unknown_method_callback` с Python-методами:
- строк: `upper`, `lower`, `islower`, `isupper`, `isspace`, `isdigit`, `isalnum`, `isalpha`, `isascii`, `strip`, `lstrip`, `rstrip`, `replace`, `title`, `split`, `splitlines`, `capitalize`, `count`, `find`, `rfind`, `startswith`, `endswith`, `format`, `join`;
- словарей: `keys`, `values`, `items`, `get`;
- списков: `count`.

`append` в этом наборе нет.

Прототип в scratchpad (выброшен) проверил на minijinja 3.0.4:
- свой объект `Object` с `ObjectRepr::Seq` над `Mutex<Vec<Value>>` и методом `append` в `call_method`;
- в макросе с вложенными циклами harness он дал `read, find, ls`;
- `length`, `count`, `join`, вывод `['read', 'find', 'ls']` и сравнение с литералом списка совпадают с Jinja2;
- методы, которых объект не знает, уходят в колбэк `pycompat`.

Затронутые модули: только ядро, `src/jinja.rs`. Граф не меняется. Контракты из таблицы «Источники правды» не меняются, кроме generated `Cargo.lock` (его обновляет cargo).

## Goals / Non-Goals

**Goals:**
- `_partials/agents/meta.jinja` и `knowledge/README.md.jinja` harness v0.3.3…v0.4.5 рендерятся без правок;
- метод, которого нет в наборе, по-прежнему ошибка, а не пустая строка.

**Non-Goals:** полная совместимость с Jinja2; изменяемые словари и прочие мутирующие методы.

## Decisions

**D1. Не-мутирующие методы — `minijinja_contrib::pycompat`.** Зависимость `minijinja-contrib = { version = "3.0.4", features = ["pycompat"] }`, версия ровно в такт с `minijinja`. Колбэк ставится в `Jinja::new` через `set_unknown_method_callback`. Набор методов — набор `pycompat` (Context).
- *Почему.* Его пишет автор minijinja, он сопровождается вместе с движком, семантика сверена с Python. Свой набор был бы тем же кодом, только непроверенным.
- *Отвергнуто.* Собственная реализация `endswith` и прочих: дублирование.
- *Цена.* Новая зависимость; список библиотек в `CLAUDE.md` дополняется.

**D2. `append` — изменяемый список rootstock.** Тип `MutableList(Mutex<Vec<Value>>)` реализует `minijinja::value::Object`:
- `repr` — `Seq`;
- `get_value` по индексу;
- `enumerate` — `Seq(len)`;
- `call_method("append", [x])` добавляет `x` и возвращает `none`.

Прочие имена и `append` с другим числом аргументов дают `UnknownMethod`. Тогда minijinja передаёт вызов колбэку `pycompat`, и, например, `count` работает. Отравленный `Mutex` даёт ошибку рендера `InvalidOperation`, не панику. Список создаёт глобальная функция `__rootstock_list()`.

**D3. Литерал `[]` в `{% set x = [] %}` подменяется при загрузке исходника.** Перед компиляцией каждый исходник проходит через функцию `rewrite_list_literals`. Это текст `render_str` и текст, который отдаёт загрузчик подключений. Функция заменяет `[]` на `__rootstock_list()` только в блочном теге, чьё тело после снятия `-`/`+` у разделителей целиком — `set <имя> = []`; пробелы любые.

Сканер идёт по тексту и пропускает:
- комментарии `{# … #}`;
- выражения `{{ … }}`;
- содержимое `{% raw %}…{% endraw %}`;
- строки в кавычках внутри тегов.

Остальной текст не меняется ни в одном байте.

`append` у любого другого списка остаётся `UnknownMethod`, а колбэк в этом случае даёт ошибку с подсказкой: «`append` works only on a list created with `{% set name = [] %}`». Другие списки — литерал с элементами, результат фильтра, `namespace(x=[])`.
- *Почему.* minijinja строит литерал внутри движка, перехватить его там нельзя (Context). Подмена узкая: она трогает ровно форму, которой пользуется harness и типичные шаблоны Jinja2, и только её.
- *Отвергнуто.* Переписывать шаблон в конвертере `import-copier`: старые теги рендерятся без конвертации, а запись на диск подменила бы чужой текст. Отвергнут и форк minijinja с изменяемыми литералами: его пришлось бы сопровождать.
- *Цена.* В выдержке исходника, которую minijinja печатает при ошибке рендера, у такой строки стоит `__rootstock_list()` вместо `[]`. Номера строк и столбцы до места подмены не сдвигаются.

**D4. Где действует.** Колбэк, функция и подмена живут в одном `Environment`. Поэтому методы работают везде, где rootstock рендерит шаблон. `eval_bool` (выражение `when`) не подменяет: `set` в выражении не бывает, а не-мутирующие методы там работают через колбэк.

## Risks / Trade-offs

- [Python-методы `pycompat` расходятся с Python в краевых случаях] → паритет с Copier 9.19 проверяет `stage2-parity` на всех комбинациях ответов harness.
- [Автор шаблона вызовет `__rootstock_list()` сам] → это обычный изменяемый список, вреда нет. Имя с префиксом, чтобы не столкнуться с ответами.
- [Сканер D3 ошибётся на экзотическом синтаксисе, например на изменённых разделителях] → разделители rootstock не настраиваются (ТЗ: §Template format). При ошибке сканера литерал просто не подменяется, и `append` даёт явную ошибку, а не тихий результат.
